# E2E-тесты эвристики VND

Тестируется актуальная эвристика `vnd.heuristic.heuristic_vnd.solve` → `vnd.heuristic.common.run_vnd`:
стартовое размещение → спуск по 1-swap (`local_search` / `n_step`, first improvement) → один улучшающий
шаг по 2-swap (`improve`) → повтор, пока 2-swap находит улучшение. Legacy-эвристики, `artifacts/`
и MIP-решатели в e2e-тестах не участвуют.

```bash
python -m pytest tests/e2e -v      # ~7 с
```

## Детерминизм

Единственный источник случайности — `generate_y_start` (`random.sample`). Остальное детерминировано:

- `swap` / `swap_2` перебирают соседей в фиксированном порядке (открытые центры по возрастанию индекса, внутри — закрытые);
- улучшением считается только строго большее ρ (`>`), берётся первый такой сосед;
- follower при равных `d` выбирает центр с меньшим индексом (строгое `<`).

Поэтому при фиксированном старте требуется **точное** совпадение итогового `y` и всего пути поиска.

## Как устроен прогон

`tests/e2e/conftest.py`, фикстура `run_traced(problem, p, V, y_start) -> (rho, y, trace)`. Продакшен-код
не меняется: через `monkeypatch` подменяется `generate_y_start` (возвращает заданный старт), а `n_step`,
`local_search`, `improve` оборачиваются «шпионами», которые только записывают принятые шаги.
`trace.cycles` — циклы VND: список принятых шагов 1-swap и принятый шаг 2-swap (или `None`).

## Данные

- **Задача 7×7** (`e2e_cases.tiny_problem`, p = 3, V = 59): целые `c`, `d`. Подобрана перебором случайных
  задач так, чтобы из разных стартов встречались все ветки. При V = 59 старты имеют ρ ≤ 0, т.е. поиск
  проходит через отрицательные ρ. В обоих итоговых оптимумах у одного клиента равные `d` у двух открытых
  центров — проверяется разрешение равенств.
- **`datasets/20_20_15.txt`**, p = 5 и p = 10, V = 10000. Пять стартов покрывают: три цикла VND; 2-swap
  ни разу не сработал; 2-swap сработал дважды подряд (без шагов 1-swap между); шаги 1-swap после 2-swap;
  остановка в глобальном и в неглобальном оптимуме.

## 1. Эталонные тесты (`test_golden.py`)

Ожидаемые `y`, ρ и путь — константы в коде теста; при прогоне ничего не вычисляется.

**Откуда константы.** Один раз, вне тестов, задача решена **независимой реализацией** (свой follower,
свои окрестности, сравнение стоимостей f вместо ρ, без кода из `vnd/`), повторяющей описанный порядок обхода.
Дополнительно:

- глобальный минимум стоимости найден полным перебором: 7×7 — C(7,3) = 35 размещений, f* = 52;
  20×20 — C(20,5) = 15 504 (f* = 9615.992677674925) и C(20,10) = 184 756 (f* = 9942.547276716443).
  Так размечено, какие ответы глобальные, а какие нет (p = 10: f = 9975.308730092336 > f*);
- стоимости f = 60, 52, 56 для задачи 7×7 пересчитаны вручную.

Константы не взяты из текущего кода: совпадение `vnd/` с независимой реализацией и есть первая проверка.

Проверяется не только ответ, но и путь — иначе сломанная фаза может случайно привести к тому же ответу
(см. мутацию `max_iters=3` ниже: ответ иногда совпадает, путь — нет).

## 2. Метаморфные тесты (`test_metamorphic.py`)

Два прогона с одного старта на исходных и преобразованных данных. Решение и путь сравниваются точно;
ρ — точно, где арифметика точная, иначе с допуском 1e-9.

| Преобразование | Ожидание | Почему выполняется в этой реализации |
|---|---|---|
| V → V + 1024 | y, путь те же; ρ + Δ/m | все сравнения — ρ(y) = (V − f(y))/m при общем V, порядок по ρ = порядок по f; follower от V не зависит |
| c → 4c, V → 4V | y, путь те же; ρ → 4ρ **точно** | умножение на степень двойки не меняет округлений: f и V − f масштабируются точно |
| c[i][j] → c[i][j] + a_j | y, путь те же; ρ − Σa_j/m | follower назначает каждого клиента ровно на один центр, поэтому f(y) сдвигается на Σa_j для всех y |
| d → 4d | всё совпадает **точно** | argmin и равенства по d в follower не меняются при положительном множителе-степени двойки |
| d[i][j] → d[i][j] + b_j | всё совпадает **точно** | порядок центров по d для каждого клиента и равенства сохраняются (b_j целые) |
| перестановка клиентов | y, путь те же; ρ с допуском | follower считает клиентов независимо; меняется только порядок суммирования в `total_cost` |

`test_cases_cover_both_phases` — служебная проверка, что выбранные старты задействуют 1-swap, 2-swap,
несколько циклов и случай без 2-swap.

**Не выполняется и не тестируется:** перестановка центров. Задача симметрична, но реализация — нет:
перестановка меняет порядок обхода соседей в `swap` / `swap_2` (а значит, какой улучшающий сосед будет
первым) и разрешение равенств в follower.

Ограничение: ошибку, одинаково проявляющуюся на исходных и преобразованных данных (например, follower
выбирает max вместо min), метаморфный тест не поймает — её ловят эталонные тесты.

На данных 20×20 (вещественные значения) точность отношений со сдвигами и перестановкой опирается на то,
что разные размещения не имеют стоимостей, совпадающих до ошибки округления; на целочисленной задаче 7×7
арифметика точная.

## 3. Инварианты результата (`test_invariants.py`)

Для всех 35 стартов задачи 7×7, пяти стартов 20×20 и шести прогонов `solve(seed=...)` без подмен:

- допустимость: `y` бинарный, ровно p единиц;
- согласованность: возвращённое ρ равно `rc(y)`;
- монотонность (для фиксированных стартов): ρ не хуже стартового;
- критерий остановки: у самого результата нет соседа с бо́льшим ρ в 1-swap и в 2-swap. Это локальная
  оптимальность относительно этих окрестностей, **не** глобальная. Соседи перебираются через `itertools`,
  независимо от `vnd/neighborhoods.py`.

Критерий остановки выполняется потому, что `run_vnd` завершается, только когда `improve` не нашёл
улучшения после `local_search`, а `local_search` дошёл до точки без улучшающего 1-swap. Оговорка: если
`local_search` упрётся в `max_iters=100`, 1-swap-оптимальность не гарантирована. На реальных данных
это не наблюдалось: при p = 15 спуск из случайных стартов сходится за 27–46 шагов (50×50 и 80×80).

## Проверка, что тесты могут падать

Каждая мутация вносилась в `vnd/` временно, после прогона откатывалась. Число упавших тестов:

| Мутация | golden | metamorphic | invariants |
|---|---|---|---|
| `n_step`: `>` → `>=` | 5 | 0 | 0 |
| `improve`: `>` → `>=` | 1 | 0 | 5 |
| `improve` всегда возвращает `y` | 5 | 1 | 26 |
| follower: min → max | 8 | 1 | 0 |
| follower: при равенстве больший индекс | 3 | 0 | 0 |
| `run_vnd`: выход после первого цикла | 5 | 1 | 16 |
| `swap`: обход закрытых центров в обратном порядке | 8 | 0 | 0 |
| `rho`: знак `(f − V)` | 8 | 17 | 0 |
| `local_search`: `max_iters=3` | 5 | 0 | 0 |

Каждую мутацию поймал хотя бы один вид тестов; эталонные — все.

## Чего тесты не проверяют

- Качество эвристики (как часто находится глобальный оптимум) — неоптимальный ответ не ошибка.
- Задачи крупнее 20×20 и поведение при достижении `max_iters`.
- Legacy-эвристики (`heuristic_vnd_legacy1/2`), MIP-решатели, `artifacts/`.
- Вырожденные входы (p = 0, p = n, бесконечные `d`).
- Сам `generate_y_start`: старт подменяется; прогоны с `seed` проверяют только инварианты.
